# 새 팀 세우기

팀마다 **데이터는 따로, 코드는 하나**로 간다.
생기팀 것은 손대지 않는다. 새 팀은 빈 DB 를 새로 만들어 거기에 설치한다.

| | 생기팀 | 새 팀 |
|---|---|---|
| 데이터 | 지금 그대로 | 빈 상태로 새로 |
| 계정·비밀번호 | 따로 | 따로 |
| 주소 | 지금 주소 | 새 주소 |
| 코드·화면 | 같은 저장소 | 같은 저장소 (한 번 고치면 같이 반영) |

---

## 준비물

- Supabase 계정 (무료로 프로젝트 하나 더 만들 수 있다)
- Vercel 계정 (지금 쓰는 것 그대로)
- 그 팀 팀장의 회사 메일 주소

---

## 1. 새 DB 만들기 — 10분

1. Supabase 에서 **New project**. 이름은 팀 이름으로 (예: `team-보전`)
2. 지역은 **Northeast Asia (Seoul)**
3. 만들어지면 왼쪽 메뉴 **SQL Editor** → **New query**
4. `setup.sql` 파일을 통째로 붙여넣고 **Run**
5. "Success" 가 뜨면 끝. 표·권한·함수가 전부 만들어졌다

## 2. 서버 함수 올리기 — 5분

Supabase 왼쪽 메뉴 **Edge Functions** 에 세 개를 올린다.
코드는 저장소 `supabase/functions` 폴더에 있다.

| 함수 | 하는 일 |
|---|---|
| `pre-register-member` | 팀원을 미리 등록 (이름·메일만) |
| `register-director` | 실장 등록 |
| `admin-reset-password` | 비밀번호 초기화 |

## 3. 주소 연결하기 — 10분

1. Vercel → **Add New Project** → **같은 GitHub 저장소**를 고른다
2. 환경변수 두 개를 넣는다 (Supabase → Settings → API 에서 복사)
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Deploy

> 저장소를 같이 쓰므로, 앞으로 **코드를 한 번 올리면 모든 팀 사이트가 같이** 새 버전이 된다.
> 표를 새로 만드는 변경(드물다)만 팀마다 SQL 을 한 번씩 돌리면 된다.

## 4. 첫 팀장 만들기 — 5분

1. Supabase → **Authentication** → **Users** → **Add user**
   - 메일: 그 팀 팀장의 회사 메일
   - 비밀번호: `1234` (본인이 처음 들어와서 바꾼다)
   - **Auto Confirm User** 켜기
2. **SQL Editor** 에서 한 번 실행 (메일·이름·팀 이름만 바꿔서)

```sql
update public.profiles
   set role = '팀장', status = '승인',
       name = '홍길동',
       team_name = '보전팀',
       sort_order = 10
 where email = 'lead@hdi21.co.kr';
```

3. 그 팀장이 새 주소로 들어가 OTP 등록 → 비밀번호 변경
4. **팀원관리** 화면에서 팀원들을 등록하면 끝

---

## 그 팀에서 처음에 할 일

- **팀원관리** → 그룹 만들기 → 사람 넣기 → 「그룹장으로」
- **팀원관리 맨 아래** → 삭제 비밀번호를 `0000` 에서 바꾸기
- 팀원들에게 **주소 + 비밀번호 1234** 를 알린다
- 모두 들어오면 **2단계 인증(OTP) 필수**를 켠다

## 알아둘 것

- **팀장은 팀마다 한 사람**이다 (DB 가 막는다)
- 실장은 **그 팀만** 본다. 여러 팀을 한 화면에서 보는 기능은 없다 — 분야 실장 체계에 맞춘 것이다
- 삭제 비밀번호 기본값은 `0000`, 팀원 초기 비밀번호는 `1234`
- 팀 사이에 자료가 오가는 길은 **없다**. 사람이 둘 다 쓰려면 양쪽에 계정이 따로 있어야 한다
